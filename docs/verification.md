# Verification boundaries

## Automated checks

- Exact structural parser with bare ampersands, inequalities, emails, type/code/HTML text, reserved-tag attacks, duplicate envelopes, size bounds and ASCII integer scores.
- Visible/gold separation, literal identity substitution, unknown placeholders and identity collisions; state/current packet equality with reviewed inputs, assignment metadata validation, source working-tree and dataset-job hashes, derived-history archive verification and analysis-seal/threshold integrity.
- Weighted upper-tail calibration, 101 boundary, weight-only ESS, planning output allowance versus actual API ceiling.
- Full 450-case/60-pair allocation with unique family cells; class/source/domain constraints and all-pair 150-case specificity selection.
- Two-way finite-cluster algebra, missing bounds, eight-test Holm family, zero-variance handling, nested state clustering and seeded null diagnostics.
- Canonical barrier admission, late/missing-member termination, failure-log disk errors, queued-block cancellation, collection before new submission, shared pending poller, accepted-batch recovery, collected replay, no duplicate billing, unknown acceptance and held reservations.
- Cross-study $450/$500 guards, full-disk snapshot failure, second-runner lock rejection, consistent snapshot and corrupt-archive refusal.
- Mocked native batch request/result/custom-ID contracts and no retries on ambiguous POST timeouts; complete opaque response-block/signature retention and final-answer-only parsing.
- Official Inspect `.eval` writer/reader, core run → report → replay, HTML escaping and no gold in samples.
- Full fake state workflow: 240 core-history calls producing 30 selected distinct helpful Turn-1 prefixes, 90 genuine Turn-2–4 suffix calls, 150 actual extractor calls and 450 protocol decisions. Replaying the state stage makes zero further submissions.

Tests forbid real HTTP transports and require no provider secrets. GitHub Actions tests Linux/Windows with Python 3.11/3.12. Local verification does not assert that another OS has already passed CI.

## Required research and account checks

A software build cannot supply human adjudication, upstream data rights/diversity, actual endpoint access, hosted checkpoint/quantisation, current prices or native-state acceptance on the user's accounts. The supplied paid preset fails closed until those configuration-specific evidence gates are completed. The replay probe archives four-turn/branch/mutation results but deliberately leaves `passed: false` for review.

No model API spend, real pilot, upstream trace download or confirmatory collection is performed during this implementation. No study findings are claimed. Fixture scores and repeatable fake transports are not evidence of model behaviour.

Native ControlArena trajectory export is not claimed: the available export is a versioned text-audit mapping read from official Inspect logs. A future native importer requires a pinned compatible ControlArena contract. The live Together path is explicitly synchronous and requires verification of the exact hosted ID and reasoning-state semantics before study use.

The input-token bound is deliberately conservative (`4 × full native payload UTF-8 bytes + 4096`), includes opaque-state bytes and assumes no cache savings. It must be checked against provider token counting before `token_bound_verified` is enabled. Finite exposure is conditional on verified token/billing semantics, actual API caps and reconciliation of external charges; configuration assumptions are not mathematical guarantees about an untested endpoint.

An older restored snapshot can omit all local evidence of later submissions. The restore runbook therefore requires a provider listing/charge audit before paid work resumes. Normal crash recovery from the latest local journal automatically retains the acceptance uncertainty.
